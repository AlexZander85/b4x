# ADR: H3 реализация — путь B (минимальный рукописный H3 поверх quic.Transport)

**Статус:** принято (владелец), фиксация по итогам ревью Фазы 3 (§8.1)
**Дата:** 2026-08-29
**Контекст:** design E-H3 §2.1; реализация `src/transport/warp/h3session.go` (путь B);
шпаргалка брифа (`WARP_NESTED_H3_REVIEW_BRIEF.md`).

## Контекст

Design §2.1 предписывал путь A — quic-go/http3 поверх `quic.Transport`. При реализации
выявлены ограничения `http3.Transport` для диалекта CF: extended-CONNECT capsule-семантика
(CONNECT-IP), дисциплина контрольного стрима и преамбулы SETTINGS, минимальный QPACK
без динамической таблицы. Обоснование отклонения приведено в коде (wire-форма сверена
с pinned usque-клоном `api/masque.go` и его connect-ip-go форком), но владельцем
подписано не было — организационная дыра: следующий ревьюер обязан трактовать это как
несоответствие.

## Решение

**Путь B подтверждён:** минимальный рукописный H3 поверх `quic.Transport` — CID 20,
SETTINGS {0x276:1}, extended CONNECT с ровно проверенным набором заголовков
(`:method CONNECT`, `:protocol cf-connect-ip`, `:scheme https`, `:authority IP:port`,
`capsule-protocol ?1`, `user-agent` пустой). Владение диалектом осознанно принимается:
trade-off — поддержка QPACK-минимума и wire-дисциплины на нас, взамен полный контроль
и сверка с pinned usque-клоном + реальными векторами warp-socks.

## Вердикт: cf-connect-proto / pq-enabled на H3 — НЕ отправлять

1. **Принцип проекта — паритет wire-формы с доказанными в проде реализациями.** Обе
   продакшн-проверенные ветки против реального CF (H3-ветка usque, минимальный H3
   warp-socks) эти заголовки на H3 **не шлют**; отправка была бы непроверенным
   отклонением от доказанной wire-формы с неизвестным риском отказа эджа.
2. **Механизм уже покрыт стандартом:** роль `cf-connect-proto` на H3 выполняет штатный
   псевдозаголовок `:protocol = connect-ip` (в коде уже кодируется);
   `cf-connect-proto` — проприетарный механизм H2-эпохи CF, на H3 избыточен.
3. **Спека Пути B** перечисляет ровно три QPACK-поля — без `cf-connect-proto`;
   расхождение было только с картой брифа, унаследовавшей H2-заголовки. Эта запись
   закрывает расхождение; шпаргалка брифа обновлена (PATCH-29).
4. Добавление заголовков потребовало бы живой проверки против CF, запрещённой
   consent-правилом (BLOCKED_TARGET_VALIDATION) — отгрузка непроверенного отклонения.

**Условие пересмотра:** если полевая сессия с консентом покажет отказы H3-CONNECT,
которых нет на H2, — добавление заголовков (`encodeLiteralNameLine`, по образцу
`:protocol`) — первая гипотеза для проверки; патч малый.

## Последствия

- Шпаргалка брифа обновлена по этим двум пунктам (в связке с PATCH-29: 700 мс —
  warp-гейт, 600 мс — WG-гейт; наследование параметров гейта 1:1 от H2 — вердикт A7).
- Оба отклонения имеют письменный вердикт владельца; следующие фазы ревью трактуют
  их как подписанные решения, а не несоответствия.
